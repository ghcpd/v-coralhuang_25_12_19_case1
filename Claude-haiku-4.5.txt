## Core Requirements

### 1. Candidate Table Features

* **Row Selection**: Checkboxes for multi-select candidates
* **Bulk Actions**: Apply status updates to multiple selected candidates

---

### 2. Status Management

* **Validation Rules**:

  * Valid transitions: `Submitted → Interviewing → Rejected/Accepted`
  * Once `Rejected` or `Accepted`, status is **immutable**
  * Block updates that don't change the status
* **Concurrency Protection**: Prevent simultaneous updates to same candidate
* **Transaction Safety**: Bulk operations must be atomic (all-or-nothing)

---

### 3. Professional UI/UX

* **NO Raw JSON**: Format all data displays properly
* **Status Badges**: Color-coded pills

  * Submitted: blue
  * Interviewing: yellow
  * Rejected: red
  * Accepted: green
* **Data Formatting**:

  * Reports: Visual charts for status distribution and trends
  * Match Results: Progress bars for scores, formatted skill lists
  * Dates: User-friendly format (e.g., "Dec 19, 2025")
  * Skills: Comma-separated lists, not semicolons
* **Loading States**: Show spinners during async operations, disable buttons to prevent duplicate clicks
* **Error Handling**: Inline error messages, NO `alert()` boxes
* **Empty States**: Friendly messages when no data
