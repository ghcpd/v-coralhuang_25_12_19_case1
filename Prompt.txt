You are a **frontend software engineer**.

Your goal is to design and implement a **Recruitment Management Dashboard** that is usable, consistent, and production-quality.

You may **modify, refactor, or redesign any part of the provided codebase** as needed to complete the task.
You are **not required to preserve the original structure or implementation**, as long as the final result satisfies the requirements.

The application should be implemented using **HTML, CSS, and JavaScript**.

---

## Core Objective

Build a **functional and polished Recruitment Management Dashboard** that supports:

* Managing candidate data
* Viewing and interacting with recruitment status
* Handling complex table interactions
* Maintaining consistent UI state across views
* Providing a clean, professional user experience

The primary goal is **correctness, usability, and clarity**, not adherence to any existing implementation.

---

## Functional Requirements

### 1. Candidate Management & Table Interactions

The dashboard must provide a candidate table that supports:

* Searching candidates by name, email, or skills
* Sorting by key fields (e.g. submission date, status, match score)
* Pagination with stable behavior when filters or search conditions change
* Row-level interactions (selection, inline actions) without conflicts

All table interactions should work together predictably and consistently.

---

### 2. Candidate Status Updates

The system must support updating candidate status with the following behavior:

* Enforce valid status transitions only
* Provide immediate visual feedback when an update is triggered
* Prevent duplicate or conflicting updates
* Handle failures gracefully, with clear error messaging
* Keep the UI state consistent after updates (no stale data)

---

### 3. State Synchronization

Ensure consistent state across all relevant views, such as:

* Candidate list
* Summary metrics or reports
* Candidate detail or match views (if present)

Any change to candidate data should be reflected across the dashboard without requiring a manual refresh.

---

### 4. UI Quality & Visual Polish

The dashboard should demonstrate strong UI craftsmanship:

* Beautiful design
* Clear layout structure (navigation, controls, content areas)
* Consistent spacing, typography, and alignment
* Clear visual hierarchy between primary and secondary information
* Readable and well-structured tables
* Meaningful visual cues for status, selection, loading, and errors
* Subtle, purposeful interaction feedback

The UI should feel **intentional and professional**, not experimental or purely functional.

---

### 5. Loading and Error Handling

Provide appropriate UI feedback for:

* Data loading states
* Ongoing user actions (e.g. status updates)
* Errors and exceptional cases

The interface should remain stable and usable during these states, without layout jumps or confusing transitions.

---

## Technical Freedom & Constraints

* You may restructure files, logic, and UI as needed
* You may refactor or replace existing implementations
* Choose sensible defaults and abstractions
* Focus on clarity, maintainability, and correctness
