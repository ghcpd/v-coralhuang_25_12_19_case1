# Recruitment Management Dashboard

You are a **frontend software engineer** tasked with building a **production-quality Recruitment Management Dashboard** using **HTML, CSS, and JavaScript**.

You may **modify or redesign any part** of the provided codebase. The goal is a functional, polished, and user-friendly dashboard.

---

## What You Must Build

### 1. Candidate Table with Full Interactions
- **Search**: Filter by name, email, or skills (live filtering)
- **Sorting**: Sort by submission date (asc/desc), status, or candidate ID
- **Pagination**: Page controls (prev/next, page size selector, current page display)
- **Row Selection**: Checkboxes for multi-select
- **Bulk Actions**: Apply status updates to multiple selected rows

### 2. Status Management
- **Server-side Validation**: Reject invalid status transitions (e.g., can't change rejected candidates back)
- **Duplicate Prevention**: Block updates that don't change the status
- **Concurrent Protection**: Prevent simultaneous updates to the same candidate
- **Immediate Feedback**: Show visual confirmation and handle errors gracefully
- **State Sync**: Auto-refresh table, reports, and match views after updates

### 3. Professional UI/UX
- **NO Raw JSON**: Never show `JSON.stringify()` output on the page
- **Formatted Data Display**:
  - Reports: Visual cards/charts showing status distribution and trends
  - Match Results: Progress bars for scores, formatted skill breakdowns
  - Dates: User-friendly format (not ISO strings)
  - Skills: Properly formatted lists, not semicolon strings
- **Status Badges**: Color-coded pills (Submitted: blue, Interviewing: yellow, Rejected: red)
- **Loading States**: Show "Loading..." or spinners during async operations
- **Empty States**: Friendly messages like "No candidates found"
- **Error Handling**: Inline error messages, not `alert()` boxes
- **Button States**: Disable during operations to prevent duplicate clicks

### 4. Deliverables
Submit complete source code plus a **README.md** with:
- How to install and run locally
- Key features and interactions
- Design decisions and tradeoffs
